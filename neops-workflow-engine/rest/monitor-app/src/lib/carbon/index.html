    The Carbon kit

    Svelte 5 components (runes, TypeScript strict) that emit the Carbon v11 DOM that carbon-components-angular 5.65 renders, on @carbon/styles 1.101.0 with the neops web SDK’s global overrides. Whatever a screen built from this kit shows is what the Angular port renders: every component names its cca counterpart in its header comment, and the classes, roles and child structure match the cca templates.

    The kit is primitives, not page compositions: layouts and patterns belong to the screens.

    Use

    // once, in the layout of a Carbon route group:
import '$lib/carbon/styles/index.scss'

import Button from '$lib/carbon/primitives/Button.svelte'
import { Add, Copy } from '$lib/carbon/icons'
import ComboBox from '$lib/carbon/wc/ComboBox.svelte' // registers a custom element; client only (ssr = false)
    • Styles. styles/index.scss = fonts.scss (IBM Plex, served by the monitor) + carbon.scss (all of @carbon/styles, as the SDK compiles it, plus the zone classes .cds--white … .cds--g100)
    • tokens.scss (motion, shell sizes, --neops-ground) + neops-sdk.scss.
    • neops-sdk.scss reproduces the SDK’s and the client’s global overrides 1:1: no theme at :root (white-theme fallbacks), the #f4f4f4 .cds--content ground, the g100 [data-carbon-theme] header scope, .cds--label with 0.7rem above it, the global h3 page title, the 46rem header panel, the spacing helpers, thin scrollbars and the rest (the file lists what it leaves out). It stays loadable nested under a selector (a host can scope it in a class). Its only deviations swap a hard-coded white-theme colour for the token with the same white value, so the g100 review theme stays legible.
    • Type. Use Carbon’s type classes (cds--type-heading-03, cds--type-body-01, cds--type-label-01, …) or Carbon’s token values in component CSS. The kit compiles the classes (a kit addition in neops-sdk.scss: neither the SDK nor @carbon/styles emits them), so they work in the app and inside a scoped host. The Angular port adds the same @include type-classes to the client’s styles. Never style type with raw sizes, and never leave a heading on browser defaults.
    • Themes. Content runs Carbon’s white theme on the #f4f4f4 ground: put fields and tables on white surfaces. The header is g100 (Header sets the scope). A g100 zone anywhere else is for review only (Theme).
    • Icons come from carbon-icons-svelte (the @carbon/icons names cca’s cdsIcon takes). Screens import them from $lib/carbon/icons (a curated re-export; add the ones a screen needs), or deep from carbon-icons-svelte/lib/<Name>.svelte.
    • Rules (ESLint-enforced for this folder): no $app/* (the kit also runs outside SvelteKit), no legacy $lib/components. Raw <cds-*> elements appear only under wc/.

    Overlay placement

    Menus place themselves: placeOverlay (internal/place.ts, pure, tested) puts an overlay below its anchor, or above when it does not fit below and there is more room above, aligned to the anchor’s start or end edge and never outside the viewport; overlay (internal/overlay.ts) applies it. In production the list joins the browser’s top layer (popover="manual", fixed), follows its anchor on resize and closes when anything scrolls. It follows an anchor that moves just after it opened (a modal still sliding in on Carbon’s entrance transform) until the anchor stays put, and again from the start of any transition or animation around the anchor that begins later, so its height cap is the room the anchor really has; the cap never reaches past the viewport’s 8 px margin. It is placed by the height it shows (its rows, up to its own CSS cap), so a list that flips above its field stays on the field. In place inside a Modal, it moves out to the modal container (the body clips and fades what it holds; elsewhere it leaves a masking ancestor), as cca appends to body; a list that stays in the body (an open cds-dropdown, a field’s suggestion list) lifts the fade while it is open, as Carbon does for its auto-aligned dropdowns; Escape in such a list closes only the list, and a Modal with scrolling content keeps focus and scrollIntoView 6rem clear of its fade (scroll-padding-block-end); hasScrollingContent means it may scroll: the fade, the region role and the tab stop apply only while the content really overflows (measured, as Carbon React and cca do), and scrolled to its end the last block clears the fade. cover lays the overlay over its anchor at the anchor’s size instead: Tooltip float places a copy of its popover container that way, so Carbon’s own CSS aligns the tooltip and its caret while no box around the trigger clips it. OverflowMenu always places; OverflowMenuPane places with place (DataTable’s row menu). Both are exported from $lib/carbon for v3 overlays (the kit owns them; v3 imports them, never the reverse).

    Deviations from cca that the port must know

    • Host elements. cca renders its own element names (<cds-tag>, <cds-table>); the kit renders span/div with the same classes, roles and children.
    • Light DOM where the dossier planned web components. OverflowMenu, Tooltip, Toggletip and Popover are light-DOM Svelte, as cca’s are: the web components’ shadow DOM blocks the SDK’s .cds--overflow-menu-options override and their floating menus move to document.body. Only the list-box widgets (combo box, dropdown, multi-select) wrap @carbon/web-components; their visible label is a light-DOM .cds--label so the SDK’s label override applies.
    • Top layer, not body. cca appends overflow menus and modals to body. The kit’s menus join the top layer in production, placed by placeOverlay; the data table’s row menu is one list for all rows.
    • Modal footer at 48 px. The footer and its buttons are 48 px with the label centred (Carbon: 64 px with a top-aligned label), and a body that does not scroll ends 32 px above it. The client adds the same override to its global styles.
    • Custom pieces, labelled in their components: the data table’s sticky trailing actions column, its empty / no match / error blocks and stale bar, rowSurface, the side-nav footer toggle, UIShell, FormGroup.
    • Accessibility additions over cca: aria-invalid / aria-describedby on every field, aria-current in navs and steps, aria-expanded / aria-controls on toggles, a real h2 naming the modal.

    Disabled with a reason

    OverflowMenuItem.shortcut (+ keyshortcuts for aria-keyshortcuts) shows an entry’s key at its end in secondary text, as Carbon Menu’s cds--menu-item__shortcut (cca: a trailing label in the option template); a menu with shortcuts takes the reasoned-menu width.

    Button and OverflowMenuItem take disabledReason (custom: cca has only native disabled). The control stays focusable (aria-disabled="true", Carbon’s disabled look, a visible focus ring), ignores activation, and is described by the reason: in the button’s tooltip (an icon-only button keeps its label as its name and gains the reason as a second tooltip line), or as a 12 px second line under a menu entry, which stays in the arrow-key order. Button disabledBy takes the id of a notice already on screen that says why: disabled the same way, described by the notice, and no tooltip repeats it. The reason (and Tooltip’s detail) is RichText: a string, or parts where { mono } renders as unbroken Plex Mono code (a grant copies verbatim); the description a reader hears is the plain joined text. OverflowMenu note adds one closing helper line that describes the whole menu (“Ask an administrator.” once for several entries). Native disabled without a reason is unchanged.

    DataTable

    Typed columns (DataTableColumn<Row>: key, header, sortable, value, compare, align, width) and a cell snippet; rowId keys selection and expansion. Sorting cycles none → ascending → descending (aria-sort on the header), and search filters the given rows, unless mode="external", where both only report (onsort, bound search). Selection (selected ids) shows cca’s batch-action bar with batchActions; expandedRow makes rows expandable; rowActions adds the sticky ⋮ column (menu keyboard: Enter/Space/Arrow Down open on the first entry, Arrow Up on the last, arrows, Home/End, Escape and Tab close and return to the trigger). States: loading (skeleton), empty (no rows), no match (search), error (+ onretry), stale (a bar over the last known rows, + onrefresh). Sizes xs 24 · sm 32 · md 40 · lg 48 (default) · xl 64; zebra off by default. rowSurface="layer" (default) is Carbon’s own #f4f4f4 rows in a white container; background makes rows white, which is what a table on the #f4f4f4 page needs (carbon-stack §3: tables sit on white surfaces), so the v3 lists use it. For the port: the SDK’s generic table (generic-table.component.scss) paints container, toolbar, header and pagination $background but leaves rows on Carbon’s layer, so today’s client tables match layer; background is a v3 change the Angular side adopts. The row ⋮ shows at rest (Carbon’s cds--data-table--visible-overflow-menu; Carbon’s default shows it on hover and focus).

    Opt-in additions for the v3 list grammar (defaults unchanged):

    • layout="fixed": table-layout: fixed, declared widths hold and the column without one takes the rest; every body cell is one line with an ellipsis and the row keeps its Carbon height whatever the content (cells are centred, no block padding). overflow-x: clip, so the table never scrolls sideways and the ⋮ column never draws its “overflowing” rule. column.truncate: false leaves a column unclipped (a button whose tooltip must show).
    • toolbarSize="sm" | "lg": the toolbar’s height independent of the row size (sm adds cds--table-toolbar--sm); the search takes the same size.
    • sticky: the toolbar and the column header stick to the page’s scroll, not an inner box (separate from maxHeight). Any overflow other than visible or clip on an ancestor captures sticky, so it needs layout="fixed". --neops-sticky-offset on an ancestor moves both down (a band the page sticks above the table).
    • rowTabindex(row, i) and onrowkeydown(e, row, i) for a one-Tab-stop table with roving row focus; rowTabindex wins over the onrowclick default, and Enter still calls onrowclick unless the hook prevents the default. Every parent row carries data-row-id.
    • rowCount + rowIndexOffset: aria-rowcount on the table (the header row counts), aria-rowindex 1 on the header row and offset + 2 on the first body row.
    • column.headerContent: custom content for an unsortable header; headerAfter(column): content after any header’s label, outside its sort button (a legend toggletip), not while loading.
    • The ⋮ column is exactly its button wide in both layouts (auto: width: 1%, which holds even when every other column declares a width; fixed: the button size) and has no block padding.
    • Header labels carry no title (cca adds one equal to the label).
    • Loading keeps the loaded shape: the ⋮ track holds its button’s box, header labels sit where the loaded ones do. column.hideHeader names a column for assistive tech only (a row-actions column), loading or not. With layout="fixed" rows are one height in both states; an auto-layout table’s row height still follows its content.
    • rowActionsNote(row): one closing line for a row’s menu (the overflow menu’s note: “Ask an administrator.” once for several refused entries).
    • openRowMenu: a row id whose menu is open at mount without taking focus (a documented state such as the flip near the bottom edge).
    • rowClass(row): extra classes on a parent row (a caller’s transient mark, e.g. rows that just arrived).
    • Sticky: the header’s end cell stays above the body’s sticky ⋮ cells while rows scroll under it, and a header whose popover is open (a legend toggletip) rises above its sticky neighbours. The skeleton’s header labels sit where the loaded ones do (no 16 px jump on arrival).

    Pagination: size sm 32 · md 40 (default, as Carbon and cca; the icon buttons were lg before) · lg 48; itemLabel(n) names the items, singular and plural, in both the known and unknown range; with no totalItems the right side reads “Page N” as text (cca pagesUnknown) and pageItems ends the last page’s range at its last item.

    Status

    The kit has no status pattern. Engine statuses render with StatusTag from $lib/v3/status over the reviewed map in $lib/v3/core/status.ts (fill only when a person must act, one glyph per family); it is built from the kit’s Tag. The kit never imports $lib/v3: the dependency runs v3 → kit only.

    Tests

    npx vitest run src/lib/carbon: DataTable sorting, selection, search, states, expansion and the row-menu keyboard; OverflowMenu; Pagination; the form fields; the web-component wrappers (properties, not string booleans); shell, modal and overlay focus behaviour; tabs, switcher, accordion, code snippet.

    Known gaps

    • carbon.scss compiles all of @carbon/styles (≈ 950 KB raw, ≈ 100 KB gzip), as the SDK does; subset it later.
    • Modal has no body scroll lock (it would touch document.body); the caller adds it in production.
    • The row menu always opens downwards; near the bottom of a short page it can extend below the table.
    • Not built: DatePicker, TreeView, Tile, ContainedList, file uploader, charts (@carbon/charts-svelte).
