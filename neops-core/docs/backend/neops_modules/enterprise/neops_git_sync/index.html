    neops_git_sync

    Bidirectional sync between (multiple) neops instances and a git repository - branch aware!

    It handels one YAML file per task with optional .j2 sidecar files for Jinja templates (readable diffs, syntax highlighting). Can import neops_task export .yml files.

    • neops → git happens automatically on every task save (signal).
    • git → neops requires explicit setup — choose from internal scheduler, NeopsTask (cron/webhook/pre-run), or management command.

    How it works

    Direction Trigger What happens
    neops → git task saved (signal) export YAML + .j2, commit, push
    neops → git task renamed (signal) rename files atomically in one commit
    neops → git task archived (signal) delete file from git (default) or keep with archived: true
    neops → git task hard-deleted (signal) delete files, commit, push
    git → neops periodic pull / management command import changed YAMLs; deleted YAML renames task _ARCHIVED_ and soft-deletes
    git → neops .yml file detected normalize to .yaml + sidecars, import, commit conversion

    A thread-local flag prevents import-from-git from re-triggering the push signal (no loop).

    Setup

    1. Add to NEOPS_PLUGINS in your .env:

    NEOPS_PLUGINS=neops_git_sync

    2. Configure credentials — via the generic save_credentials management command (app key neops_git_sync):

    # HTTPS + personal access token (username + token = Basic auth)
python manage.py save_credentials neops_git_sync --url https://github.com/org/repo.git --username bot --password ghp_xxx
# HTTPS + Bitbucket project/repository access token (token without username = Bearer auth)
python manage.py save_credentials neops_git_sync --url https://bitbucket.example/scm/proj/repo.git --password BBDC-xxx
# SSH
python manage.py save_credentials neops_git_sync --url git@github.com:org/repo.git --key-file ~/.ssh/id_ed25519
# public repo, pull-only — no auth needed
python manage.py save_credentials neops_git_sync --url https://github.com/org/repo.git
# show current configuration (secrets masked)
python manage.py save_credentials neops_git_sync

    …or in the neops admin under Django 3Party Credentials, app key neops_git_sync:

    field value
    url repo URL (https://github.com/org/repo.git or git@github.com:org/repo.git)
    username git username (HTTPS only)
    password personal access token (HTTPS)
    key SSH private key PEM (SSH only)

    3. Set environment variables:

    NEOPS_GIT_SYNC_ENABLED=true
NEOPS_GIT_SYNC_BRANCH=main
NEOPS_GIT_SYNC_LOCAL_PATH=/var/neops/git_sync
NEOPS_GIT_SYNC_SUBDIR=tasks                      # repo folder for task files ("" = repo root); README.md stays at the root

# Push (neops → git)
NEOPS_GIT_SYNC_AUTO_PUSH=true                    # push on every task save/archive/delete signal (default: true)
                                                  # set to false for pull-only / git-as-SoT mode
NEOPS_GIT_SYNC_DELETE_ON_ARCHIVE=true            # delete file from git when task is archived (default: true)
                                                  # set to false to keep with archived: true instead
NEOPS_GIT_SYNC_EXPORT_BLACKLIST=["^_only_git.*"] # skip files matching these patterns on push

# Pull (git → neops)
NEOPS_GIT_SYNC_AUTO_PULL_MIGRATION=true          # register Celery Beat PeriodicTask at migrate time
NEOPS_GIT_SYNC_PULL_INTERVAL_MINUTES=5           # interval for internal scheduler (migration-time only, default: 5)
NEOPS_GIT_SYNC_IMPORT_BLACKLIST=["^_only_git.*"] # skip files matching these patterns on pull

# File format
NEOPS_GIT_SYNC_JINJA_SIDECAR=true                # extract Jinja template fields to .j2 sidecar files (default: true)
NEOPS_GIT_SYNC_JINJA_SIDECAR_MIN_LINES=15        # min template lines to extract to sidecar; shorter stays inline (default: 15)

# Git author
NEOPS_GIT_SYNC_GIT_AUTHOR_NAME=NeOps Git Sync
NEOPS_GIT_SYNC_GIT_AUTHOR_EMAIL=git-sync@neops.io

# GUI
NEOPS_GIT_SYNC_WEB_URL=https://github.com/org/repo  # repo base URL for GUI deep links (empty: no links)

    4. Enable automatic pull — pick one or combine:

    • Internal scheduler — set NEOPS_GIT_SYNC_AUTO_PULL_MIGRATION=true before manage.py migrate; see Pull options below
    • NeopsTask — create a pull task in the GUI, trigger via cron, webhook, or manually; see Pull options below
    • Management command — run neops_git_sync pull directly; see Management commands

    If neops is your only source of truth and nobody edits the git repo directly, no pull setup is needed.

    File format

    Each task exports as:

    My_Task.yaml                    # metadata + non-template kwargs
My_Task.template.j2             # Jinja template (if JINJA_SIDECAR=true and >= JINJA_SIDECAR_MIN_LINES)
My_Task.mapping_template.j2     # additional template fields

    The YAML format is compatible with python manage.py neops_task --export --multi-file, extended with optional .j2 sidecar files for Jinja templates and an archived: true field for soft-delete state.

    Push (neops → git)

    Enabled by default. On every task save, rename, archive, or hard-delete a Django signal fires and queues a Celery task that commits and pushes to git. A 30-second debounce prevents duplicate pushes when neops saves a task multiple times internally for one logical operation.

    Set NEOPS_GIT_SYNC_AUTO_PUSH=false to disable all signal-based pushes. Use this to lower I/O and you want to push peridocally by cron - or when git is the source of truth and neops should only consume from git, not write back.

    On-demand push options: - NeopsTask with direction: push or both — see Sync via NeopsTask - Management command — neops_git_sync push-all or push <id>

    Pull (git → neops)

    Pull is not automatic by default. Pick one or combine:

    Internal scheduler

    Set NEOPS_GIT_SYNC_AUTO_PULL_MIGRATION=true before running manage.py migrate. This registers a Celery Beat PeriodicTask directly — no NeopsTask needed. The interval is read from NEOPS_GIT_SYNC_PULL_INTERVAL_MINUTES at migration time. Changing the env var afterwards has no effect — update the PeriodicTask record in the django-celery-beat admin instead.

    Sync via NeopsTask

    Create a NeopsTask in the GUI with provider enterprise-git-sync and set direction in the task kwargs:

    direction effect
    pull pull from git, import changed tasks into neops
    push export all neops tasks to git
    both pull then push

    Trigger options: - GUI — run the task like any other NeopsTask; output appears in the execution log - neops_cron — schedule at a fixed interval via the neops_cron plugin - neops_webhook — create a Webhook record pointing at the task’s uniquetaskname; configure your git host to POST on push events for an immediate pull; auth (basic, token) handled by neops_webhook - pre-run — attach the pull task as a pre-run task of another NeopsTask; see below

    Pull before task execution (pre-run)

    Add the pull task (provider enterprise-git-sync, direction: pull) as a pre-run task of any NeopsTask whose definition must be current at execution time. The pull then runs inside that task’s own execution chain — no matter whether the run was started from the GUI, a cron schedule, or a webhook — so a change merged to the branch seconds earlier is imported before the task executes.

    This closes the gap between “merged to the branch” and “next periodic pull”, and it is the recommended freshness guarantee on instances that cannot receive webhooks.

    Choosing pull triggers per instance

    Instance Recommended setup
    dev / inbound webhooks possible neops_webhook on git push events + periodic pull as backstop
    prod / no inbound webhooks frequent periodic pull + pre-run pull on critical tasks

    Frequent polling is cheap: every pull first checks the remote branch head with git ls-remote — a single outbound ref lookup with no data transfer — and skips the full fetch/merge when the branch hasn’t moved. A 1-minute interval is fine even against rate-limited git hosts.

    Importing

    From the Django admin export

    The Django admin task export produces .yml files with inline Jinja templates. These are auto-detected by extension and normalized on pull or import-all:

    1. Drop the .yml file(s) into the git repo and push
    2. On the next pull (or run import-all manually), neops detects the .yml, imports the task, re-exports it as .yaml + .j2 sidecars, and commits the conversion — the .yml is gone after
    neops: normalize Import_Devices.yml → yaml

    You can also trigger the conversion manually without going through git:

    python manage.py neops_git_sync import Import_Devices.yml
# or convert everything in one shot:
python manage.py neops_git_sync import-all

    Archiving

    neops → git

    NEOPS_GIT_SYNC_DELETE_ON_ARCHIVE controls what happens when a task is archived (soft-deleted) in neops:

    Setting behaviour
    true (default) file deleted from git; task stays soft-deleted in neops DB
    false file kept in git with archived: true; README index shows ~~strikethrough~~; pulling into another neops instance will soft-delete the task there too

    Hard-deleting a task always removes the file from git regardless of this setting.

    git → neops

    If a .yaml is deleted from git and neops pulls, the task is renamed to {name}_ARCHIVED_{timestamp} and soft-deleted — freeing the name and identifier for reuse. This behaviour is not affected by NEOPS_GIT_SYNC_DELETE_ON_ARCHIVE.

    GUI integration (GraphQL)

    The plugin exposes a read-only gitSyncStatus query for GUI panels (requires authentication, like all queries):

    query {
  gitSyncStatus {
    enabled
    autoPush
    branch
    webUrl            # deep-link base from NEOPS_GIT_SYNC_WEB_URL, "" when unset
    lastSyncedAt      # ISO 8601 — last successful remote sync (pull or push)
    lastError
    lastErrorAt
    dirty
    head { shortSha author authoredAt message }
    log(limit: 10) { sha shortSha author authoredAt message }
  }
}

    The data is a cached projection (Redis) written by the worker after every sync — web processes never touch the local clone or the git credentials, so no extra volumes are needed for web pods. log holds the last 20 commits; lastSyncedAt is the freshness indicator (“last pull: X min ago”). Whether the plugin is loaded at all is visible via the existing appSettings { modules { name } } query.

    Task file deep link: {webUrl}/blob/{branch}/{slug}.yaml (GitHub) — build client-side from webUrl + branch.

    Management commands

    # Pull from git and sync all changed tasks into neops
python manage.py neops_git_sync pull

# Push every task in neops to git
python manage.py neops_git_sync push-all

# Push a single task by PK
python manage.py neops_git_sync push 42

# Remove a task's file(s) from git
python manage.py neops_git_sync delete "My Task Name"

# Import a single YAML/YML file into neops (and normalize if .yml)
python manage.py neops_git_sync import My_Task.yaml

# Import every file in the local clone into neops (normalizes .yml files)
python manage.py neops_git_sync import-all

# Inspect the local clone — shows unsynced tasks, legacy .yml files,
# orphaned sidecars, and tasks in repo but not in neops
python manage.py neops_git_sync status
python manage.py neops_git_sync log -n 20

    Example status output:

    branch:  main
HEAD:    a1b2c3d4e5f6  neops: update task My Task
clean:   True
  (nothing to commit)

legacy .yml (run import-all to convert):
  ~ Import Devices  (Import_Devices.yml)

in repo but not in neops:
  ? SyncLocationDirect  (SyncLocationDirect.yaml, SyncLocationDirect.mapping_template.j2)

  ! Old_Task.template.j2
