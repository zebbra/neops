    OIDC Authentication

    Server-side OIDC authentication using django-allauth with a one-time authorization code exchange pattern. OIDC tokens never reach the frontend.

    Architecture

    sequenceDiagram
    participant Browser
    participant Frontend as Frontend SPA
    participant Backend as Neops Backend
    participant Keycloak as OIDC Provider

    Note over Frontend,Backend: Login Flow
    Frontend->>Backend: GraphQL: appSettings { oidcProviders, auth { localLoginEnabled } }
    Backend-->>Frontend: [{id, name, loginUrl}], localLoginEnabled: false
    Browser->>Backend: GET /auth/oidc-login/<provider>/?client=<origin>
    Backend->>Backend: Pin frontend callback URL in session (origin matched against allowlist)
    Backend-->>Browser: 302 → /accounts/oidc/<provider>/login/
    Browser->>Backend: GET /accounts/oidc/<provider>/login/
    Backend->>Keycloak: Authorization code flow (server-side)
    Keycloak-->>Browser: Login page
    Browser->>Keycloak: User authenticates
    Keycloak->>Backend: Callback with authorization code
    Backend->>Backend: Validate code, create/link user, profile sync
    Backend->>Backend: Create one-time code (384-bit, 60s TTL)
    Backend->>Backend: Destroy Django session
    Backend-->>Browser: 302 → /auth/callback?code=<one-time-code> (Referrer-Policy: no-referrer)
    Frontend->>Backend: GraphQL: exchangeOidcCode(code) [rate limited: 20/min/IP]
    Backend->>Backend: Burn code (mark used immediately), validate expiry
    Backend-->>Frontend: {accessToken, refreshToken}
    Frontend->>Backend: Subsequent requests with Bearer <neops-jwt>

    Note over Frontend,Backend: Logout Flow (SLO)
    Frontend->>Backend: GET /auth/oidc-logout/?provider=keycloak
    Backend->>Backend: Destroy Django session
    Backend->>Keycloak: Fetch discovery document
    Backend-->>Browser: 302 → Keycloak end_session_endpoint (with client_id + post_logout_redirect_uri)
    Keycloak->>Keycloak: Terminate SSO session
    Keycloak-->>Browser: 302 → Frontend /login

    Configuration

    Backend

    OIDC providers are stored in Django’s SocialApp table and managed via the seed_oidc_providers command.

    Environment variables:

    Variable Default Description
    NEOPS_JWT_PRIVATE_KEY_PATH — Path to the RSA private PEM that signs Neops JWTs (RS256). Required for token-service plugins (neops_auth_django, neops_auth_allauth); server boot fails fast when it is unset or unreadable. Local dev: make generate-jwt-keys writes the pair to backend/secrets/ and prints the two .env lines. Docker/K8s: mount the PEM (e.g. from a K8s Secret) and point this at the mount path.
    NEOPS_JWT_PUBLIC_KEY_PATH — Path to the RSA public PEM used to validate Neops JWTs and to publish JWKS at /.well-known/jwks.json. Same generation and mount notes as the private key. Mount the same key pair to every replica, or a token signed by one replica is rejected by another.
    AUTH_PROVIDERS_CONFIG_PATH — Path to provider seed JSON file
    NEOPS_FRONTEND_CALLBACK_URL http://localhost:4242/auth/callback Default frontend callback URL for code delivery (validated at startup)
    NEOPS_FRONTEND_CALLBACK_URLS [] Additional callback URLs for multi-frontend deployments (comma-separated). The initiating frontend is matched by origin at /auth/oidc-login/<provider>/; only configured URLs are ever redirected to.
    NEOPS_FRONTEND_LOGIN_URL http://localhost:4242/login Frontend login URL for post-logout redirect
    NEOPS_PUBLIC_URL "" Browser-facing origin for provider loginUrls. Required when GraphQL traffic reaches the backend through a Host-rewriting hop (e.g. neops-gql-gtw).
    NEOPS_REFRESH_TOKEN_REUSE_GRACE_SECONDS 150 Idempotency/reuse grace window for rotated refresh tokens. Within it a re-presented just-rotated token returns the SAME successor (multi-tab races and lost-response retries converge on one chain). Benign-vs-theft is decided from the DB (revoked_at + the replaced_by link), so a cache miss within grace denies a single request but never triggers a revoke-all. Should exceed the client refresh interval. 0 = strict single-use. The cached successor is stored encrypted (Fernet keyed off SECRET_KEY).
    NEOPS_REFRESH_REUSE_REVOKE_ALL_ON_DETECT True On detected reuse of a revoked refresh token (past the grace window, or with no live successor), revoke every active refresh token for the user. Disable for single-request denial only.
    RATELIMIT_IP_META_KEY — META key holding the real client IP behind a proxy/ingress. Required in multi-user prod behind a shared-IP ingress — otherwise all users collapse into one per-IP rate-limit bucket and the fleet-wide refresh loop self-throttles. Point it at a header your ingress sets and strips from inbound requests (e.g. HTTP_X_REAL_IP). Leave unset only when REMOTE_ADDR is the real client IP.
    USE_OIDC / OIDC_CONFIG_PATH False / ./oidc-config.json DEPRECATED legacy passthrough: when the config file exists it is served verbatim via appSettings.oidcConfig so pre-allauth frontends keep their in-browser SSO. Without it, an inert boot config plus useOidc: false is served so old frontends degrade gracefully to local login.
    NEOPS_OIDC_CODE_LIFETIME_SECONDS 60 One-time code TTL in seconds
    NEOPS_OIDC_RATE_LIMIT 20/m Rate limit for the code exchange endpoint (django-ratelimit format). When non-empty, a shared cache backend (Redis/Memcached) is required — it does not silently fall back to LocMemCache. The allauth boot check (neops_auth_allauth.E002) hard-fails startup if CACHES.default is a per-process LocMemCache, because per-worker counters would make the effective ceiling workers × configured rate; a missing django_ratelimit install hard-fails too (E001). Set to "" to opt out of rate limiting entirely (the boot check is then skipped). See RATELIMIT_IP_META_KEY for the shared-IP-ingress caveat.
    ACCOUNT_DEFAULT_HTTP_PROTOCOL https Protocol for allauth-generated URLs

    Provider seed JSON format:

    {
  "providers": [
    {
      "provider_id": "keycloak",
      "name": "Keycloak",
      "client_id": "neops-auth",
      "secret": "<client-secret>",
      "settings": {
        "server_url": "https://keycloak.example.com/realms/neops/.well-known/openid-configuration"
      }
    }
  ]
}

    Run the seed command:

    python manage.py seed_oidc_providers --config /path/to/providers.json

    Frontend

    The frontend fetches available OIDC providers and the localLoginEnabled flag from the appSettings GraphQL query:

    query {
  appSettings {
    auth {
      active
      type
      localLoginEnabled
    }
    oidcProviders {
      id
      name
      loginUrl
    }
  }
}

    When localLoginEnabled is false (set by the allauth plugin), the username/password form is hidden.

    Each provider’s loginUrl points to the backend’s OIDC login wrapper — /auth/oidc-login/<provider>/ — not allauth’s /accounts/oidc/<provider>/login/ endpoint directly. The wrapper pins the initiating frontend’s callback URL into the session (matched by the ?client=<origin> query parameter, falling back to the Referer origin, validated against the configured callback allowlist) before it 302-redirects to allauth’s login endpoint. This first hop is what lets several frontends share a single backend. The frontend initiates login via full-page navigation: window.location.href = provider.loginUrl (optionally appending ?client=<its-own-origin>).

    After the OIDC flow completes, the backend redirects to /auth/callback?code=<one-time-code>. The frontend exchanges the code for Neops JWTs:

    mutation {
  exchangeOidcCode(code: "<one-time-code>") {
    accessToken
    refreshToken
  }
}

    The exchangeOidcCode mutation is unauthenticated by design — the one-time code is the credential. It is rate limited at 20 requests/minute per IP via django-ratelimit (configurable via NEOPS_OIDC_RATE_LIMIT).

    Profile Sync

    On each OIDC login, the backend syncs the following claims from the identity provider:

    Claim Django field Behavior
    email user.email Updated if changed; skipped if email conflicts with another user
    given_name user.first_name Updated if changed
    family_name user.last_name Updated if changed

    Username is set only on initial user creation (derived from the email local part, with collision retry).

    Claims are read from a merged view of the IdP’s userinfo response and the decoded ID token (userinfo wins where it provides a value; the ID token fills gaps). This matters because Keycloak’s stock mappers add roles/verification claims to the ID token, not the userinfo endpoint, by default (and SOCIALACCOUNT_STORE_TOKENS=False means there is no access token to read).

    Role sync (authorization)

    On every OIDC login the backend mirrors the token’s role claim into user.roles: resource_access.<client_id>.roles (Keycloak client roles) when present, otherwise a top-level roles list (Microsoft Entra ID app roles, and other providers that emit roles that way). This is authorization-critical:

    • Roles present in the token but missing in Django are auto-created; roles absent from the token are removed from the user. A new SSO user derives their roles solely from this claim.
    • If neither claim is present (misconfigured mapper, wrong scope), existing roles are left untouched (absent is treated as “unknown”, not “no roles”) and a warning is logged — so a realm misconfiguration cannot silently strip everyone’s roles.

    Microsoft Entra ID: define the app roles on the app registration with values equal to the Neops role names and assign them to users or groups; Entra emits them as the ID token’s roles claim with nothing else to configure.

    Required Keycloak configuration: the client’s client roles protocol mapper must add resource_access to a token the backend can read. Since IdP tokens are not stored, that means the ID token (enable Add to ID token on the mapper) or the userinfo response (Add to userinfo). With the default mapper (access-token only) SSO users receive no roles. Verify with Clients → <client> → Client scopes → Evaluate that resource_access appears in the ID token.

    Security

    • No OIDC tokens on the client: The entire OIDC authorization code flow runs server-side. Only Neops-issued RS256 JWTs reach the frontend.
    • One-time codes: 384-bit entropy, 60-second TTL, single-use with database-level locking (SELECT FOR UPDATE). Codes are burned (marked used) immediately on lookup, before expiry validation — preventing any replay window.
    • Referrer-Policy: All code-carrying redirects include Referrer-Policy: no-referrer to prevent code leakage via the HTTP Referer header.
    • Rate limiting: The exchangeOidcCode mutation is rate limited per IP using django-ratelimit (default: 20/min). Configurable via NEOPS_OIDC_RATE_LIMIT; set to "" to disable.
    • URL validation: NEOPS_FRONTEND_CALLBACK_URL is validated at settings load time — misconfiguration raises ImproperlyConfigured at startup rather than creating an open redirect at runtime.
    • Token lifetimes: Neops access tokens live 15 minutes (NEOPS_JWT_ACCESS_LIFETIME_MINUTES), refresh tokens 7 days (NEOPS_JWT_REFRESH_LIFETIME_DAYS). The SPA refreshes on a ~2-minute interval (well under the access lifetime), rotating the refresh token each time; the ~150s reuse grace window comfortably exceeds that interval so a lost-response retry lands inside it.
    • Token storage: SOCIALACCOUNT_STORE_TOKENS = False — allauth does not persist IdP tokens.
    • Email auto-linking: SOCIALACCOUNT_EMAIL_AUTHENTICATION = True auto-links social accounts by email. All configured OIDC providers must be trusted first-party IdPs that verify email addresses.
    • Session cleanup: Django sessions are destroyed immediately after code creation.
    • Full OIDC SLO: Logout terminates the Keycloak SSO session via RP-initiated logout with client_id. The logout endpoint deliberately accepts anonymous requests (the SPA holds only Bearer JWTs and the Django session is destroyed at code creation); the discovery fetch is protected by a per-IP rate limit and an http(s)-scheme check on the operator-configured server_url. Without an id_token_hint (IdP tokens are never stored), newer Keycloak versions may show a logout confirmation page unless the client’s Valid post logout redirect URIs are configured.

    Logout

    The logout chain ensures complete session termination:

    1. Frontend revokes its refresh token via the logout(refreshToken) mutation (fire-and-forget)
    2. Frontend clears local state (localStorage tokens, Apollo cache)
    3. Frontend navigates to /auth/oidc-logout/?provider=<provider-id> (anonymous — the Django session was already destroyed at login completion)
    4. Backend fetches Keycloak’s end_session_endpoint from discovery (rate-limited, scheme-validated)
    5. Backend redirects to Keycloak with client_id and post_logout_redirect_uri
    6. Keycloak terminates SSO session and redirects back to /login

    Database Migrations

    The OidcAuthorizationCode model requires migrations:

    python manage.py migrate neops_auth_allauth

    This creates the neops_auth_allauth_oidcauthorizationcode table and registers a Celery periodic task for code cleanup (every 5 minutes).

    Local Development

    Docker Networking

    The Docker Compose stack includes a pre-configured Keycloak instance. A key networking consideration:

    • KC_HOSTNAME is http://localhost:8081 (browser-facing URLs and iss claim)
    • KC_HOSTNAME_BACKCHANNEL_DYNAMIC: "true" makes server-to-server (backchannel) requests return URLs based on the request origin. This allows the Django backend to reach Keycloak via http://keycloak:8080 (Docker DNS) while browsers use http://localhost:8081.

    The server_url in the provider seed uses http://keycloak:8080/realms/neops/.well-known/openid-configuration (Docker-internal). Issuer validation succeeds because the iss claim always uses KC_HOSTNAME regardless of backchannel dynamic.

    Starting the Stack

    cd docker
COMPOSE_FILE=docker-compose.base.yml:docker-compose.keycloak.yml:docker-compose.backend.yml:docker-compose.backend-keycloak.yml \
  docker compose up -d

    Migrations and seed_oidc_providers run automatically on backend startup (defined in docker-compose.backend-keycloak.yml). Keycloak admin console: http://localhost:8081 (admin / admin).

    Keycloak client-roles mapper (roles won’t sync without it)

    Because SOCIALACCOUNT_STORE_TOKENS = False, the backend never sees the OIDC access token — it reads roles from the ID token and userinfo only (see Role sync). A client-roles mapper that emits resource_access.<client_id>.roles to the access token alone (Keycloak’s stock default) therefore leaves every OIDC user with no roles. The bundled dev realm (docker/realm-export.json) ships an oidc-usermodel-client-role-mapper on the neops-auth client with id.token.claim=true and userinfo.token.claim=true so this works out of the box; if you point local dev at your own realm, replicate that mapper (verify via Clients → neops-auth → Client scopes → Evaluate that resource_access appears in the ID token).

    Postgres Upgrade (11 → 16)

    The Keycloak Postgres image was upgraded from postgres:11-alpine to postgres:16-alpine. Postgres 16 cannot read data files from Postgres 11. If upgrading from an existing setup:

    # Remove old Keycloak data volume
rm -rf docker/data/keycloak

# Start fresh — Keycloak will re-import realm-export.json on first boot
docker compose -f docker/docker-compose.keycloak.yml up -d

    The realm export is Keycloak’s JSON format (not a Postgres dump), so it is independent of the Postgres version and works without modification.

    Troubleshooting

    Symptom Cause Fix
    No OIDC buttons on login page Providers not seeded Run seed_oidc_providers or check AUTH_PROVIDERS_CONFIG_PATH
    “Invalid authorization code” Code expired, already used, or malformed Re-initiate login; check clocks are synchronized
    “Too many requests” Rate limit exceeded on code exchange Wait and retry; check for frontend retry loops
    “The identity provider returned an error” Keycloak misconfiguration Check Keycloak logs; verify redirect URIs match
    Redirect loop after login NEOPS_FRONTEND_CALLBACK_URL misconfigured Ensure it points to the frontend’s /auth/callback route
    Backend can’t reach Keycloak Docker networking issue Verify KC_HOSTNAME_BACKCHANNEL_DYNAMIC: "true" is set and server_url uses http://keycloak:8080/...
    Logout doesn’t terminate Keycloak session oidcProviderId not in localStorage Verify handleOidcTokens stores the provider ID from the JWT auth_provider claim
    ImproperlyConfigured on startup Invalid NEOPS_FRONTEND_CALLBACK_URL Ensure the URL has a valid http:// or https:// scheme and a netloc
